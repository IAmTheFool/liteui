# Platform notes

LiteUI runs on **Windows** (Direct3D 11 and Direct2D) and **Linux under Wayland** (EGL and OpenGL ES 3.0, with Cairo and Pango for text). The layout engine, event dispatch, scrolling, focus and the whole public API are shared, so most code behaves identically. This page is the one-stop list of where the platforms **differ**, with a link to the detail for each item.

## Support matrix

| | Windows | Linux |
|---|---|---|
| Window system | Win32 | **Wayland only** (xdg-shell) |
| Rendering | Direct2D on a Direct3D 11 swap chain (GPU, WARP software fallback) | EGL + **OpenGL ES 3.0** |
| Text | DirectWrite | Pango, rasterized with Cairo |
| Canvas | Direct2D on a GPU bitmap | OpenGL ES 3.0 renderer (default), or a Cairo image surface with `-DLITEUI_CANVAS_GL=OFF` |
| Pointer input | Mouse; pen and touch through `WM_POINTER*` | Mouse (`wl_pointer`); touch (`wl_touch`); pen (`zwp_tablet_v2`) |
| Image codecs | WIC (decode any format WIC supports; encode PNG and JPEG) | libpng, libjpeg (**PNG and JPEG only**) |
| Bundled presets | `msvc-*` | `gcc-*` |
| Other platforms | macOS and X11 are **not supported**; there is no DPI or output-scale handling on either backend | |

Setup, packages and flags for each are in [BUILDING.md](BUILDING.md).

## Differences at a glance

Legend for the last column: **Design** means the platforms are meant to differ, **Limit** means a known limitation, and **Bug** means the behavior looks unintended and is expected to be fixed (see [Known platform gaps](#known-platform-gaps)).

### Window and lifecycle

| Area | Windows | Linux | Kind | Details |
|---|---|---|---|---|
| Title bar | Native | Drawn by LiteUI (32 px: minimize, maximize, close) | Design | [ARCHITECTURE.md](ARCHITECTURE.md#linux-wayland) |
| Frameless window (`hideTitlebar`) | Supported | Supported | Same | [API.md](API.md#liteui-the-window) |
| `setOnCloseRequest` | Called for close requests | **Never called** | Bug | [API.md](API.md#methods) |
| `requestClose()` | Goes through the close handler | Closes immediately | Bug | [API.md](API.md#methods) |

### Drawing and canvas

The Linux column describes the default OpenGL ES 3.0 canvas backend. The Cairo fallback (`-DLITEUI_CANVAS_GL=OFF`) differs in the places noted; the full three-way table is in [CANVAS.md](CANVAS.md#platform-differences).

| Area | Windows | Linux | Kind | Details |
|---|---|---|---|---|
| Default `lineWidth` | 1 px | 1 px (**2 px** on the Cairo fallback) | Same (Cairo: Bug) | [CANVAS.md](CANVAS.md#context-state-and-defaults) |
| `setGlobalCompositeOperation` | Only `SourceOver`, `Copy` and `Lighter` honored; other values draw as source-over | All operators honored (`Multiply` costs a canvas copy per shape) | Limit | [CANVAS.md](CANVAS.md#compositing) |
| Radial gradient with inner radius | Approximated | Exact | Limit | [CANVAS.md](CANVAS.md#gradients) |
| Gradient fill on text | First stop's color only | Honored (first stop only on the Cairo fallback) | Limit | [CANVAS.md](CANVAS.md#text) |
| `strokeText` | Approximation (offset copies) | True glyph outlines (approximation on the Cairo fallback) | Limit | [CANVAS.md](CANVAS.md#text) |
| `putImageData` | Alpha-blends, respects clip | Replaces pixels, ignores clip and alpha | Limit | [CANVAS.md](CANVAS.md#reading-and-writing-pixels) |
| `getImageData` | GPU readback (flushes pending work) | GPU readback (direct read on the Cairo fallback) | Design | [CANVAS.md](CANVAS.md#reading-and-writing-pixels) |
| `measureText` width | Fractional | Rounded to whole pixels | Design | [CANVAS.md](CANVAS.md#text) |
| `Alphabetic` text baseline | Approximated (80% of line height) | Font's real baseline | Limit | [CANVAS.md](CANVAS.md#text) |
| `CanvasContext::width()/height()` | Possibly fractional | Whole pixels | Design | [CANVAS.md](CANVAS.md#the-drawing-surface) |
| Canvas memory | GPU texture, stays in video memory | GPU texture (CPU bitmap on the Cairo fallback) | Same | [CANVAS.md](CANVAS.md#performance-notes) |
| Box border | Stroked centered on the edge (half outside) | Drawn inside the box, snapped to whole pixels; radius clamped to half the shorter side | Design | [LAYOUT.md](LAYOUT.md#box-model) |
| Shadow blur, `fillText` `maxWidth` | Not implemented | Not implemented | Limit (both) | [CANVAS.md](CANVAS.md#not-available) |

### Identical on both

The layout engine (`liteui_layout`), the pointer router (`liteui_pointer`: hit-testing, bubbling, capture, click and double-click pairing, per-pointer and per-button state), the XML and SVG parsers, focus, scrolling behavior (wheel, thumb drag, content pan), tooltips, shortcuts, keyed-list reconciliation, and the `Dynamic<>` polling model are shared code, so they behave the same. Mouse, pen and touch all produce the same `PointerEvent`s on both platforms. The one behavioral wrinkle in shared scrolling code is that `Overflow::Hidden` containers still scroll, on both platforms ([LAYOUT.md](LAYOUT.md#overflow-and-scrolling)).

## Windows notes

- **Build from a developer prompt.** The MSVC presets pin `cl.exe` and leave toolchain selection to the environment. See [BUILDING.md](BUILDING.md#windows-setup).
- **Pass `/utf-8`** to MSVC so sources are read as UTF-8.
- **Console window.** A normal `int main` program also opens a console, which is where `stderr` (including profiler output) appears. If you link a GUI-subsystem executable, redirect `stderr` to see it.
- **Only Windows has profiler output.** Use the `msvc-*-profile` presets. See [PROFILING.md](PROFILING.md).
- **GPU, with a software fallback.** Rendering uses a Direct3D 11 device. If no usable GPU or driver exists, device creation falls back to WARP (Microsoft's software rasterizer), so the app still runs, only slower. A lost or reset device is recovered on the next paint.
- **Canvas cost.** Canvases live in video memory and are only redrawn when asked, but they take GPU memory proportional to their pixel size, and `getImageData` is a GPU readback. Keep canvases only as large as they need to be.
- **Compositing.** Only `SourceOver`, `Copy` and `Lighter` are honored by `setGlobalCompositeOperation`; use `clearRect` to erase.
- **Pen and touch** need Windows 8 or later (`WM_POINTER*`).
- **Close prompts work here.** `setOnCloseRequest` is honored on Windows; make sure the handler calls `forceClose()`.
- **ASan builds** copy the sanitizer runtime DLL next to each test executable. See [TESTING.md](TESTING.md#sanitizers).

## Linux notes

- **Wayland only.** There is no X11 backend. A session without a Wayland display (plain X11, SSH without forwarding, many containers) fails at startup with a `std::runtime_error` from the `LiteUI` constructor. Check `WAYLAND_DISPLAY`.
- **GPU stack.** Rendering needs EGL and **OpenGL ES 3.0** (Mesa or a vendor driver), for the window itself and not only for GL canvases. A missing driver, or one that only offers ES 2.0, fails at startup with an error that says so. A GPU reset recreates the context; three consecutive losses make the window stop updating.
- **Dependencies.** Development packages for Wayland, xkbcommon, Cairo, Pango, EGL, OpenGL ES (the `glesv2` pkg-config module, whose library also provides ES 3.0), libpng and libjpeg; the exact module list is in [BUILDING.md](BUILDING.md#linux-setup). The Wayland protocol bindings are vendored, so `wayland-scanner` is not needed to build.
- **Optional runtime tools.** Install `zenity` (or `kdialog`) for file dialogs, and `wl-clipboard` (or `xclip`/`xsel`) for the system clipboard. Without them, pickers return nothing and the clipboard stays inside your process.
- **Title bar.** LiteUI draws its own. For a custom bar, create the window with `hideTitlebar = true` and use `requestMove`, `requestMinimize`, `requestMaximize` and `requestClose`.
- **Close handling.** `setOnCloseRequest` and `requestClose()` currently skip the handler, so a "save changes?" prompt will not run. Do your confirmation in your own UI.
- **Canvas backend.** Canvases use the OpenGL ES 3.0 renderer by default. Configuring with `-DLITEUI_CANVAS_GL=OFF` switches them to Cairo, which changes the default line width (2 px) and a few other behaviors; see [CANVAS.md](CANVAS.md#platform-differences).
- **Pen and touch.** Fingers arrive through `wl_touch` and pens through the tablet protocol, whose bindings are vendored. A compositor that does not expose those devices simply never delivers such events.
- **Stroke widths.** Always call `setLineWidth` before stroking. The default is 1 px with the GL backend but 2 px on the Cairo fallback.
- **Images.** Convert assets to PNG or JPEG.
- **Redraws are synchronous.** Every timer tick redraws the whole window immediately, and the swap waits for vsync, so keep intervals as long as your animation allows.

## Writing portable apps

A checklist for code that should look and behave the same on both platforms:

- [ ] Call `setLineWidth` explicitly before every stroke.
- [ ] Use only `SourceOver`, `Copy` and `Lighter` with `setGlobalCompositeOperation` if you target Windows. Use `clearRect` to erase.
- [ ] Ship images as PNG or JPEG.
- [ ] Handle pointer input through `PointerEvent` (mouse, pen and touch share it), and end a drag in both `onPointerUp` and `onPointerCancel`.
- [ ] Treat the file pickers and clipboard as fallible: handle `std::nullopt` and empty results, and prefer `setTextWithFallback` / `getTextWithFallback` for in-app copy and paste.
- [ ] Do not rely on `setOnCloseRequest` for data safety until it is wired up on Linux. Make unsaved-changes handling part of your normal UI flow.
- [ ] Avoid pixel-exact expectations for text on the alphabetic baseline or for `measureText` widths; allow a pixel or two. Do not rely on `strokeText` or gradient text fills looking the same everywhere.
- [ ] Use `putImageData` with fully opaque pixels, or draw translucent content with `drawImage`.
- [ ] Do not give canvases more pixels than needed (they take GPU memory on both platforms), and call `getImageData` at most once per redraw (it reads back from the GPU).
- [ ] Keep `addInterval` usage simple on Windows (see [Known platform gaps](#known-platform-gaps)).
- [ ] Prefer `Size::full()` and `flexGrow` over absolute sizes so layouts adapt to the different default window chrome.
- [ ] Test on both. The shared layout code is covered by unit tests; painting and input are not.

## Known platform gaps

The items below are places where one platform lags the other or the behavior looks unintended. They are the ones to fix first, and this table is the single place to retire them from, along with the matching caveat in the linked guide.

| Gap | Affects | Where it is documented |
|---|---|---|
| `setOnCloseRequest` is never called, and `requestClose()` bypasses it | Linux | [API.md](API.md#methods), README |
| `addInterval` handles can collide after removals | Windows | [ARCHITECTURE.md](ARCHITECTURE.md#sharp-edges) |
| Default `lineWidth` is 2 px instead of 1 px | Linux, Cairo fallback only | [CANVAS.md](CANVAS.md#context-state-and-defaults) |
| `globalCompositeOperation` honors only `SourceOver`, `Copy` and `Lighter` | Windows | [CANVAS.md](CANVAS.md#compositing) |
| `putImageData` blends instead of replacing | Windows | [CANVAS.md](CANVAS.md#reading-and-writing-pixels) |
| `strokeText` is an approximation and gradient text uses the first stop | Windows, Linux Cairo fallback | [CANVAS.md](CANVAS.md#text) |
| Profiler has no probes; `recompute` and `appPaint` are never recorded | Linux (all stages), both (those two stages) | [PROFILING.md](PROFILING.md#known-gaps) |
| Keyed-list changes clear focus without `onBlur` | Both | [ARCHITECTURE.md](ARCHITECTURE.md#sharp-edges) |
| `Overflow::Hidden` containers still scroll | Both | [LAYOUT.md](LAYOUT.md#overflow-and-scrolling) |
| Images limited to PNG and JPEG | Linux | [API.md](API.md#liteui_image-decoding-encoding-and-display-conversion) |
| No DPI or output-scale handling | Both | [ARCHITECTURE.md](ARCHITECTURE.md#costs-and-trade-offs) |
